# Data & Privacy Boundaries

## Repository state

This repository is currently **public**.

The repository must therefore be treated as a publication environment, not as primary research-data storage.

## Allowed in public repository

- Public assignment information
- Public web and policy sources
- Generic analytical frameworks
- Proposal architecture
- Publicly verifiable clinic landscape information
- Sanitized matrices and process diagrams
- Aggregated or anonymized findings only when disclosure is authorized
- Final public deliverables when publication is authorized
- Sanitized retrospective case material

## Prohibited in public repository

- Interview recordings
- Verbatim interview transcripts
- Personal data or contact details
- Sensitive personal data
- Identifiable participant notes
- Unpublished clinic documents
- Confidential agreements
- Client-internal material
- Credentials, secrets or access tokens
- Raw notes that could identify individuals or reveal non-public operational details

## Fieldwork rule

If the assignment proceeds, raw fieldwork material must be stored in an approved protected environment outside this repository.

The `06-fieldwork/` branch of the architecture may contain:
- generic interview guides;
- anonymized case IDs;
- data-management instructions;
- sanitized case summaries;
- links or references to controlled storage locations without exposing credentials.

## Publication gate

No field-derived material is moved into the public repository until:
1. it is required for a public deliverable or case record;
2. confidentiality and data-protection requirements have been checked;
3. identifiers and sensitive details have been removed where necessary;
4. client/publication clearance has been obtained where required.
